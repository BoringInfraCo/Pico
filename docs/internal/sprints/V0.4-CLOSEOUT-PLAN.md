## 4. S032 — environment versus evidence attribution

> DELIVERED — implemented in `d98cd38`. Attribution v1 additive over
> S029-compatible COMPLETE operands; coverage v1 persisted; SQLite schema
> stays v6. Strict rules: isolated Bash allow→ask is Mixed, ask→deny is Mixed
> (DERIVED→UNKNOWN / UNKNOWN→BLOCKED knowledge transitions), Claude deny is
> observed environment change. Specs: `SPRINT-032.md` plus
> `SPRINT-032-inventory.md`. Historical proposal below preserved.

Current gap: `GraphDelta` compares allowlisted values without classifying
their meaning; `FindingCause` merges evidence source types from both sides.
Causes are attached only to appeared/disappeared findings. Weakened,
strengthened, and uncertain lifecycle entries carry rating deltas without
the underlying observed explanation. COMPLETE status alone must not be
treated as proof of equal discovery coverage.

First checkpoint: inventory the actual persisted snapshots, evidence, scan
diagnostics, and coverage information for every supported provider/path.
Freeze a field-to-meaning table and identify what can be justified from
historical data. If coverage or provenance must be newly persisted, specify
that write contract and legacy fallback explicitly; never backfill invented
evidence. A schema or comparison-contract change requires its own migration
and S029 compatibility evidence. Do not promise schema v6 for this slice
before this inventory is complete.

Proposed application contract:

- Classify individual relevant changes as `observed_environment_change`,
  `evidence_change`, `mixed`, or `unattributed`, with stable reason codes.
  These are proposed names to freeze in the sprint spec.
- An environment label requires comparable, supported observations on both
  sides. Loss of access, reduced coverage, unresolved identity, or missing
  evidence must not be labeled remediation or a confirmed disappearance.
- Preserve both sides' safe evidence provenance separately, including the
  relevant subject/field and known before/after values. Do not export raw
  credential material, arbitrary metadata, or full source files.
- Explain lifecycle rating changes through the same attribution service.
  Severity or confidence movement alone is not evidence of an environment
  change. State uncertainty when no supported cause is available.
- Keep S029 analysis/graph/finding contract mismatch as `NotComparable`,
  before attribution. Analysis-version changes are a separate comparison
  limitation, not an ordinary environment delta.
- Keep first-seen/reappeared claims relative to retained COMPLETE history.
  Scope uncertainty may require a suppressed/uncertain result; freeze the
  result shape before implementing the renderer.

Acceptance matrix: unchanged scans; Bash allow/ask/deny; supported approval
or boundary changes; credential and resource scope; MCP availability;
authority changes; confidence-only evidence changes; collection failure;
reduced coverage even where snapshots are COMPLETE; stale/newer incomplete
attempts; identity churn; mixed changes; unavailable legacy provenance;
contract mismatch; post-prune windows. Assert both attribution and the
absence of false remediation/disappearance. Include repeated observations
and both supported agent/provider paths where applicable. Preserve unknown
cause rather than inventing a unique cause for ambiguous multi-change cases.

## 5. S033 — stable public machine output

> DELIVERED — implemented in `15e5615`. `pico diff [<from> <to>] --json` and
> `pico history --json` emit a single JSON document; public output schema v1
> (`docs/public/output-v1.schema.json`, `docs/public/JSON-OUTPUT.md`) with
> shared DTOs, golden payloads, and fail-closed validation. Spec:
> `SPRINT-033.md`. Historical proposal below preserved.

Minimum release scope: `pico diff [<from> <to>] --json` and
`pico history --json`. Keep JSON for scan/findings/prune/doctor outside this
slice unless a concrete v0.4 acceptance case requires it.

Introduce explicit public DTOs in a shared output module; do not serialize
application structs or persistence records directly. Freeze a checked-in
schema, representative golden payloads, and consumer documentation.

Contract decisions to freeze:

- A public schema version distinct from SQLite schema, comparison tuple,
  and Pico build version; define additive and breaking-change rules.
- A tagged result with explicit ready, insufficient-history, and
  not-comparable outcomes; never make empty arrays imply an all-clear.
- Opaque scan/finding identifiers, chronological selection, timestamps,
  provenance, freshness, lifecycle, attribution, and retained-history limits.
- Stable field names/enums, null-versus-absent rules, deterministic array
  order, and equality expectations for repeated reads of unchanged state.
- Stable error codes and documented exit behavior. Preserve existing human
  command semantics. Treat query limitations as typed results, distinguish
  usage/database failures, and keep stdout as a single JSON document.
- An explicit policy for argument-parser errors; test actual subprocess
  behavior rather than promising JSON for errors clap still renders itself.
- Safe allowlisted projections, including error and diagnostic paths.
  Scan/finding IDs are opaque handles, not an invitation to query SQLite.

Acceptance: every diff outcome plus history empty/populated, stale context,
invalid/missing/pruned IDs, incomplete/reversed pairs, unsupported schema,
and I/O errors. Validate schema/goldens, parse stdout, prove read-only
digests, sweep secrets/control bytes, and compare semantic content with the
human CLI. Do not add CI failure thresholds or notifications.
