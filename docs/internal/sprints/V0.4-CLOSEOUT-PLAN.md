## 1. Review verdict

Sprint 030's normal retention path and existing regression suite pass, but
the baseline is not ready for unconditional sign-off. Close the following
gaps before expanding the public change-detection surface.

| Priority | Finding | Evidence and required correction |
| --- | --- | --- |
| P1 | Post-health failure occurs after deletion is committed | `src/application/retention.rs`, `PruneService::run`: `tx.commit()` precedes `check_health`. Reproduced with three COMPLETE units and a retained finding's JSON `evidence_ids` pointing to the oldest unit's existing evidence. Doctor initially passes; `prune --keep 2` returns a post-health error, but the oldest scan is gone and doctor now fails. Validate the resulting state inside the deletion transaction and roll back on failure. |
| P1 | Doctor echoes arbitrary malformed JSON contents | `scan_table_json_refs` carries unparseable text in `DanglingRef.id`; `render_doctor_report` prints it. A sentinel placed in malformed `finding_reasons.evidence_ids` appears in doctor stdout. Escaping control bytes does not redact secrets. Report the table, column, safe location, and failure category without raw contents; handle arbitrary unresolved string IDs similarly. |
| P2 | RUNNING refusal and retention planning race concurrent writers | Scans, the RUNNING check, the plan, and pre-health are read before the write transaction begins. A scan can start in that interval, violating the refusal contract; the retained report can also be stale. This is a code-review finding, not a reproduced concurrency test. Acquire an immediate write transaction before these reads and keep the entire operation in that snapshot. |

## 3. S031 — retention correctness follow-up

Implementation homes: `src/application/retention.rs`, `src/cli/render.rs`,
S030 persistence/integration suites, and the S030 completion addendum.

- Open existing state, require the supported schema, acquire an immediate
  transaction, then load scans, refuse RUNNING, plan, and run pre-health.
- Delete and validate post-health before commit. Build the report from that
  same snapshot. A failed health gate must leave all content unchanged.
- Remove raw malformed JSON and untrusted unresolved IDs from diagnostics;
  use bounded structural locations and stable reason codes instead.
- Preserve keep-10 / keep-at-least-2, whole-unit ordering, no-op success,
  global identity retention, and the existing two-tool MCP surface.

Acceptance: permanent regressions for the reproduced cross-scan JSON case
and malformed/valid-JSON sentinel cases; deterministic two-connection
concurrency tests without timing sleeps; zero-write refusal/no-op and
unsupported-schema proofs; retained-row digests; repeat pruning; all S030
gates. Concurrency outcomes must show either refusal of an existing RUNNING
scan or exclusion of a new writer until prune finishes, with no stale plan.

## 4. S032 — environment versus evidence attribution

Current gap: `GraphDelta` compares allowlisted values without classifying
their meaning; `FindingCause` merges evidence source types from both sides.
Causes are attached only to appeared/disappeared findings. Weakened,
strengthened, and uncertain lifecycle entries carry rating deltas without
the underlying observed explanation. COMPLETE status alone must not be
treated as proof of equal discovery coverage.

First checkpoint: inventory the actual persisted snapshots, evidence, scan
diagnostics, and coverage information for every supported provider/path.
Freeze a field-to-meaning table and identify what can be justified from
historical data. If coverage or provenance must be newly persisted, specify
that write contract and legacy fallback explicitly; never backfill invented
evidence. A schema or comparison-contract change requires its own migration
and S029 compatibility evidence. Do not promise schema v6 for this slice
before this inventory is complete.

Proposed application contract:

- Classify individual relevant changes as `observed_environment_change`,
  `evidence_change`, `mixed`, or `unattributed`, with stable reason codes.
  These are proposed names to freeze in the sprint spec.
- An environment label requires comparable, supported observations on both
  sides. Loss of access, reduced coverage, unresolved identity, or missing
  evidence must not be labeled remediation or a confirmed disappearance.
- Preserve both sides' safe evidence provenance separately, including the
  relevant subject/field and known before/after values. Do not export raw
  credential material, arbitrary metadata, or full source files.
- Explain lifecycle rating changes through the same attribution service.
  Severity or confidence movement alone is not evidence of an environment
  change. State uncertainty when no supported cause is available.
- Keep S029 analysis/graph/finding contract mismatch as `NotComparable`,
  before attribution. Analysis-version changes are a separate comparison
  limitation, not an ordinary environment delta.
- Keep first-seen/reappeared claims relative to retained COMPLETE history.
  Scope uncertainty may require a suppressed/uncertain result; freeze the
  result shape before implementing the renderer.

Acceptance matrix: unchanged scans; Bash allow/ask/deny; supported approval
or boundary changes; credential and resource scope; MCP availability;
authority changes; confidence-only evidence changes; collection failure;
reduced coverage even where snapshots are COMPLETE; stale/newer incomplete
attempts; identity churn; mixed changes; unavailable legacy provenance;
contract mismatch; post-prune windows. Assert both attribution and the
absence of false remediation/disappearance. Include repeated observations
and both supported agent/provider paths where applicable. Preserve unknown
cause rather than inventing a unique cause for ambiguous multi-change cases.

## 5. S033 — stable public machine output

Minimum release scope: `pico diff [<from> <to>] --json` and
`pico history --json`. Keep JSON for scan/findings/prune/doctor outside this
slice unless a concrete v0.4 acceptance case requires it.

Introduce explicit public DTOs in a shared output module; do not serialize
application structs or persistence records directly. Freeze a checked-in
schema, representative golden payloads, and consumer documentation.

Contract decisions to freeze:

- A public schema version distinct from SQLite schema, comparison tuple,
  and Pico build version; define additive and breaking-change rules.
- A tagged result with explicit ready, insufficient-history, and
  not-comparable outcomes; never make empty arrays imply an all-clear.
- Opaque scan/finding identifiers, chronological selection, timestamps,
  provenance, freshness, lifecycle, attribution, and retained-history limits.
- Stable field names/enums, null-versus-absent rules, deterministic array
  order, and equality expectations for repeated reads of unchanged state.
- Stable error codes and documented exit behavior. Preserve existing human
  command semantics. Treat query limitations as typed results, distinguish
  usage/database failures, and keep stdout as a single JSON document.
- An explicit policy for argument-parser errors; test actual subprocess
  behavior rather than promising JSON for errors clap still renders itself.
- Safe allowlisted projections, including error and diagnostic paths.
  Scan/finding IDs are opaque handles, not an invitation to query SQLite.

Acceptance: every diff outcome plus history empty/populated, stale context,
invalid/missing/pruned IDs, incomplete/reversed pairs, unsupported schema,
and I/O errors. Validate schema/goldens, parse stdout, prove read-only
digests, sweep secrets/control bytes, and compare semantic content with the
human CLI. Do not add CI failure thresholds or notifications.

## 6. S034 — MCP history and diff

Proposed new tools: `list_history` and `diff_scans`. Freeze names and
descriptors in the spec. `diff_scans` accepts either no IDs (latest two) or
both `from` and `to`; reject one-sided, wrong-type, empty, or extra arguments.
Keep workspace selection bound to the server's existing workspace.

Call `HistoryService` and `DiffService`, then project through S033's public
DTOs. Put transport framing in `src/mcp`; add no independent comparison,
scanning, retention, or attribution logic. Use the existing MCP protocol
conventions; this plan does not require a protocol upgrade.

Acceptance: CLI JSON and decoded MCP payload parity for all S033 outcomes;
new descriptor goldens; old `list_findings` / `get_finding` descriptor and
payload compatibility; deterministic parameter failures; no-write digests;
secret sweeps; pruned IDs explicitly not found; limitations remain visible
to agents. Read-only annotations are required. Expose no prune/doctor write
operation, scan trigger, arbitrary database query, or arbitrary path input.

## 7. S035 — evidence and independent comprehension

Build a controlled dogfood sequence with captured commands and sanitized
CLI/JSON/MCP outputs: baseline, unchanged repeat, real permission/authority
change, evidence loss/recovery, contract mismatch, and pruning. Map every
ROADMAP §8 exit criterion to an artifact and an observed result.

An independent developer who did not implement the feature or author the
fixtures must interpret final output without code access or coaching.
Record participant independence, build, inputs shown, verbatim answers,
and pass/fail per scenario. An implementing agent's proxy cannot close it.

Required questions: What changed? Why does it matter? What before/after
evidence supports that conclusion? Did the environment change, did evidence
change, or did comparison become invalid? Is the dangerous path confirmed
gone or merely unobserved? How fresh is the comparison? How does the
retention window limit first-seen claims? What supported action interrupts
the path, and what remains uncertain?

Pass only when all safety-critical distinctions are correctly understood;
any false all-clear, false remediation, or missed freshness/contract limit
requires correction and a new uncoached validation. Reuse the existing
v0.3 path-comprehension questions to address the carried independent gate
explicitly. Record that result separately rather than silently closing it.

Also collect qualitative answers to §8's learning questions: meaningful
versus noisy changes, useful retention depth, useful manual triggers, and
notification thresholds. These inform v0.5; they do not authorize its scope.

Final release gate: fmt, clippy, all-target tests with ignored tests accounted
for, schema/compatibility evidence, public-output parity, secret/read-only
proofs, and independent comprehension. Update ROADMAP and architecture only
to reflect delivered behavior. Resolve Cargo/CLI version naming deliberately
at release review (`Cargo.toml` currently says `0.1.0`); do not bump it merely
because this plan refers to roadmap phase v0.4.
